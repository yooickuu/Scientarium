# Scientarium

Портал медицинских и научных мероприятий. RU/ҚАЗ/EN, каталог и календарь, отдельные страницы мероприятий, избранное, профиль, мобильный интерфейс, управление вузами и статистика.

## Текущая архитектура

GitHub Pages размещает статические страницы, Supabase — авторизацию и PostgreSQL. Роли проверяются в базе: администратор управляет всем порталом; модератор — только своими мероприятиями; пользователь — своим профилем и избранным. Владелец защищён от понижения. Профессиональная категория не выдаёт прав доступа.

`config/public.json` содержит **только публичные** настройки Supabase. Секретные ключи в сайт не добавлять. Персональные данные, локальная база, пароли и резервные копии исключены из Git.

```sh
npm ci
npm run test:supabase
npm run build:pages
```

Сборка готовых страниц находится в `out/`. Workflow `.github/workflows/pages.yml` собирает и публикует её после отправки в `main`. На GitHub включите **Settings → Pages → Source → GitHub Actions**, затем **Actions → Publish Scientarium → Run workflow**.

Для текущего репозитория адрес: `https://yooickuu.github.io/scientarium/` (заработает после успешного Pages deployment).

## Supabase после публикации

В Authentication → URL Configuration:

- Site URL: `https://yooickuu.github.io/scientarium/`
- Redirect URLs: `https://yooickuu.github.io/scientarium/auth/confirm/` и `https://yooickuu.github.io/scientarium/auth/reset/`

Для регистрации пользователей и сброса паролей нужен **custom SMTP**. Стандартная почта Supabase ограничена адресами команды; не отключайте подтверждение email для обхода. Созданный вручную подтверждённый аккаунт может входить своим новым паролем.

SQL `001_scientarium.sql` уже выполнен в текущем облачном проекте. Повторно его не запускать. Последующие изменения базы оформляются отдельными миграциями с резервной копией. Публикация страниц не пересоздаёт базу и не очищает мероприятия/профили.

## Локальная работа

`npm run dev` использует `.env.local`. При `NEXT_PUBLIC_DATA_BACKEND=supabase` сайт работает с **настоящей облачной базой**. Для отдельной старой SQLite-версии задайте пустое значение этой переменной и перезапустите сервер. Не используйте рабочую базу для тестовых записей.

`npm run db:backup` сохраняет только локальную SQLite. Для облачных данных нужны отдельные PostgreSQL-экспорты/резервные копии. Локальная резервная копия не защищает новые облачные записи.

## Домен позже

После проверки домена и требований к размещению настройте DNS и Custom domain в Pages. В переменных GitHub Actions добавьте `PAGES_CUSTOM_DOMAIN`, затем пересоберите сайт: сборка автоматически уберёт `/scientarium` и добавит `CNAME`. Обновите адреса перенаправления Supabase.

## Проверки и ограничения

Пройдены TypeScript, статическая сборка, 6 локальных PostgreSQL-сценариев прав доступа и импорта. Публичный облачный каталог проверен. Полная визуальная/мобильная проверка и реальный вход владельца пока не выполнены. Статистика посещений приблизительная: сеансы не равны уникальным людям.
